# 设计目标与约束

> 本文档说明这个 shaderpack「为什么这么做」。任何与此冲突的实现细节，以本文档的目标为准。

---

## 1. 项目目标

**下限极低、上限极高、几乎完全写实**。

| 维度 | 目标 |
|---|---|
| 风格 | 写实（物理可信的大气、光照、色调映射），不做风格化滤镜 |
| 低端 | 低画质档要在集显/老独显上跑得动；宁可牺牲画面也不掉帧 |
| 高端 | 高画质档要能到影视级：可用的特性全部用上，不设人为上限 |
| 可维护 | 仓库结构与产物同构，改一个参数只改一个地方 |

两个直接推论：

1. **不存在"够用的画质"这种中间答案**。每个效果都要有便宜的近似和昂贵的准确实现两条路，由档位切换。
2. **不能引入"为了兼容低端而永久关掉"的负担**。低端走的是一条独立的、经过裁剪的路径，而不是给高端路径加一堆 `#if` 补丁。

### 1.1 资源预算

场景几乎不使用外部纹理（无 PBR 材质包依赖），显存预算**几乎全部**可以给渲染缓冲。因此：

- 缓冲的数量和尺寸不受"显存紧张"约束，优先考虑算法需要；
- 例如 bloom 用 8 级独立缓冲（而非单张图集 + mip 链），只为换取可调的扩散半径和更平滑的尾部；
- 唯一的真实约束是**带宽**，所以 pass 数量、渲染目标数量仍要克制。

---

## 2. 允许使用的特性

目标平台：**最新稳定版 Iris** + **RTX 30 系（Ampere）配最新驱动**。

### 2.1 Iris

全部特性标志均可用（在 `iris.features.required` / `optional` 中声明即可使用，
声明后会自动定义 `IRIS_FEATURE_<NAME>` 供代码判断）：

```
COMPUTE_SHADERS            CUSTOM_IMAGES           SSBO
SEPARATE_HARDWARE_SAMPLERS PER_BUFFER_BLENDING     HIGHER_SHADOWCOLOR
BLOCK_EMISSION_ATTRIBUTE   ENTITY_TRANSLUCENT      REVERSED_CULLING
TESSELATION_SHADERS        FADE_VARIABLE           TEXTURE_FILTERING
CAN_DISABLE_WEATHER
```

程序槽位方面的可用上限（已核对 Iris 官方文档）：

| 程序 | 可用后缀 |
|---|---|
| `setup` / `prepare` / `deferred` | 数字后缀 |
| `composite` | 无后缀 + `1`–`99` |
| `final` | 仅无后缀，输出到背缓冲 |
| `gbuffers_*` / `shadow*` | 固定名称集合 |

### 2.2 驱动 / GPU

- GLSL **4.60**（`#version 460 compatibility`），compute shader、`imageLoad/Store`、
  SSBO、`textureQueryLevels`、64 位整数等 GL 4.6 core 特性全部可用；
- Ampere 驱动提供的外观上是 `GL_KHR_shader_subgroup`、`GL_NV_shader_atomic_float`
  等扩展，**使用时必须包在 `#ifdef` 里并提供退化路径**，因为它们不属于 GL core；
- 不依赖任何画面质量相关的厂商私有行为。

### 2.3 边界

- 不允许"只有高端能跑"的强制路径：任何一个特性都要有可编译、可运行的降级方案。
- 不允许为兼容 OptiFine 而牺牲结构（本包只面向 Iris）。

## 3. 质量档位规划

档位是**编译期宏**（`options.glsl` + `shaders.properties` 的 `profile.*`），
不是运行期分支。

| 档位 | 面向 | 典型取舍 |
|---|---|---|
| 低 | 集显 / 老独显 | 大气步进降至 8–16，bloom 级数减半，无体积效果，阴影 1024 |
| **中（当前）** | 主流独显 | 大气 32 步，bloom 8 级，2×2 阴影 PCF，全分辨率延迟光照 |
| 高 | RTX 30 系 | 大气 48–64 步，更高 LUT 分辨率，更大 PCF 核，SSAO/SSR |
| 影视 | 截图 / 录制 | 全部拉满，可接受帧率折半 |

**当前仓库的参数集合视为「中档」**。所有参数应能被更高/更低档位覆盖，
因此新参数加入时必须写进 `options.glsl` 并考虑它在各档的取值，而不是直接写死。

## 4. Bloom 分级的依据

需求：**屏幕左边缘的极亮光源，其光晕要能扩散到右边缘**。

### 4.1 关键结论：级数决定"平滑度"，扩散系数决定"射程"

上采样链中，级别 `k` 读取的是 `BLOOM(k+1)`，其 texel 为屏幕的 `0.5^(k+1)`，
3×3 tent 把内容向外扩一个 texel。所以总射程是几何级数：

```
radius ≈ Σ(k=1..levels-1) 0.5^(k+1) × spread
```

实测（`spread = 1.0`）：

| 级数 | 最粗一级 texel（1080p） | 射程 radius | 直径 |
|---|---|---|---|
| 5 | 60 × 34 px | 0.469 屏 | 0.94 屏 |
| 6 | 30 × 17 px | 0.484 屏 | 0.97 屏 |
| 7 | 15 × 8 px | 0.492 屏 | 0.98 屏 |
| **8** | **7.5 × 4.2 px** | **0.496 屏** | **0.99 屏** |

两个结论：

1. **级数对射程几乎无影响**（0.469 → 0.496，几何级数收敛）。想跨屏必须调 `BLOOM_SPREAD`。
2. **级数决定最宽那一层光晕的平滑度**：5 级时最粗一级是 60×34 像素，扩散到全屏后
   会看到明显的方块/色阶；8 级时是 7.5×4.2 像素，梯度足够平滑。

因此采用 **8 级 + `BLOOM_SPREAD = 2.0`**：

```
radius ≈ 0.496 × 2.0 ≈ 0.99 屏    →  左边缘的光能到达右边缘
```

`BLOOM_SPREAD` 通过放大 tent 的采样偏移实现。源级别本身已是模糊结果，
双线性过滤会填补放大后的采样间隙，因此不会出现明显的环带。
若将来发现高 spread 下有环带，正确的解法是改成 5-tap 或 7-tap tent，而不是降低级数。

### 4.2 为什么不用单缓冲 + mip 链

| | 单缓冲 + mip 图集 | 每级独立缓冲（当前） |
|---|---|---|
| 扩散半径 | 被图集布局锁死，不可调 | `BLOOM_SPREAD` 可调 |
| 采样开销 | 全屏双向高斯，约 18 屏采样 | 约 4 屏采样 |
| 布局常量 | 图集尺寸、1px 出血、书架坐标 | 无 |
| 缓冲数 | 1 | 8（显存充裕，见 §1.1） |

### 4.3 阈值

- `BLOOM_THRESHOLD`：亮度达到此值的像素**完整**计入（权重 1）。
- `BLOOM_THRESHOLD_SMOOTH`：**比例**，不是绝对宽度。下界 = `threshold × (1 - ratio)`，
  该区间内用 `smoothstep(下界, threshold, 亮度)` 过渡。
  用比例而非绝对值的理由：改阈值时柔和程度保持相对不变。

## 5. 已作出的结构性决策（勿轻易推翻）

| 决策 | 理由 |
|---|---|
| 仓库 `shaders/` 与产物同构 | 任意文件都能在包里按同路径找到，便于对着抓帧排查 |
| 构建器只做"复制 + 占位符替换 + 生成薄壳" | 保证产物中的每段逻辑都能追溯回源文件 |
| 一个源文件可通过 `Pass.defines` 服务多个槽位 | 避免复制文件；`BLOOM_LEVEL` 是典型例子 |
| 色调映射放在 `final` 而不是 `compositeN` | `final` 是 Iris 专用于输出背缓冲的槽位，语义正确且不占用 composite 编号 |
| 曝光用独立归约（`RT_LUM`）而非读 mip | 需要在对数域做加权平均和中心权重；且与 bloom 解耦后两者可独立演进 |
| `lib/` 按域分层，域内 ≥3 文件时提供 `all.glsl` | 调用方只 include 聚合器，域内拆分对它不可见 |
| `RT_SPECULAR` / `RT_VERTEX_LIGHT` 保留 | 规划中的 labPBR 与顶点低频光照通道，见 `ARCHITECTURE.md` §5 |
